# CLAUDE.md — working rules for clinical-annotation-tools

Guidance for Claude Code (and humans) working in this repo. Read `README.md` for
what the project is and `devlog.md` for *why* past decisions were made.

## The core invariant: frozen datasets are immutable

A dataset under `datasets/<name>/` is a **frozen, versioned artifact**. Once it
exists (and especially once a run has annotated it), its bytes are the shared
source of truth for character offsets.

- **Never edit `docs/*.txt`, `manifest.jsonl`, or `sampling.json` by hand.** They
  are generated by `scripts/build_dataset.py`. Change the script, not the output.
- **Any change to cleaning, axes, N, or schema ⇒ a new version dir** (`-v2`),
  never a mutation of the existing one. Mutating a frozen dataset silently
  invalidates every run scored against it.
- The dataset is committed to git on purpose — reproducibility. Don't gitignore it.

## Reproducibility is non-negotiable

- `build_dataset.py` is **deterministic** (`SEED = 20260723`). Any code change
  must keep it so — re-running must reproduce identical bytes.
- After changing the sampler, run `--report-only` and confirm every axis hits
  its target exactly (`target == achieved`, `selected == N`). A stalled draw
  (`selected < N`) is a bug, not an acceptable outcome — see the rarity-first
  draw ordering in `devlog.md`.
- The **data pipeline stays stdlib-only** — do not add third-party deps to
  `build_dataset.py`. (Annotation may use deps: `openrouter` is the one runtime
  dependency, for API transport. Manage the env with `uv` — `uv run python …`,
  `uv add …`; the lockfile `uv.lock` is committed.)

## Model runs go in `runs/`, never in the dataset

- Predictions live in `runs/<model>/predictions.jsonl` + `run.json`, one sibling
  dir per model — **outside** `datasets/`. This keeps the input frozen and makes
  cross-model comparison mechanical.
- Every model annotates the **same bytes** with the **same schema** (`SCHEMA.md`).
  Don't invent per-model label sets or re-clean the text per model.
- Offsets are half-open `[start, end)` char offsets into `docs/<doc_id>.txt`.
  Validate that `text == doc[start:end]` before trusting a run.

## Data / licensing

- **MIMIC-IV is restricted — never commit it** (or any restricted-license data).
  This repo uses only public MTSamples. If you touch data provenance, preserve
  this boundary.
- Notes are de-identified clinical text; keep it that way.

## Decisions and deferred work

- `devlog.md` is the engineering decision log: **newest on top, record the *why*.**
  When you make a non-obvious choice or knowingly defer something, add an entry
  (mark deferrals so nothing silently falls through).
- Prefer updating `devlog.md` / the dataset card over leaving decisions only in
  commit messages.

## Keep the manual in sync

- `manual/` holds a human-readable page per CLI so a person can pick up a task
  **without AI**. When you add or change a CLI's behavior, options, or output,
  update its `manual/*.md` page in the **same commit**, and re-capture example
  output by actually running the command (examples must be real, not invented).
- Add new commands to the table in `manual/README.md`.

## Commits

- Commit or push only when asked. Branch first if on `main`.
